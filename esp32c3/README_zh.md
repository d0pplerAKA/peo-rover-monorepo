# PEO Rover — ESP32-C3 手柄 BLE 桥固件

> **一句话定位**：C3 是 Xbox 手柄与主控之间的「翻译官」——BLE 连上手柄，把摇杆/按键状态打包成主控能懂的帧，经有线串口直连 F407。它只发原始值，不做任何映射与仲裁。

---

## 1. 工程总览

C3（ESP32-C3 SuperMini，ESP-IDF v6.1）专职一件事：**把手柄状态从无线搬到有线**。

- **BLE**（NimBLE）：按目标 MAC 过滤连接 Xbox 手柄，自动扫描/连接/重连，首通知 5s 看门狗；
- **帧打包**（esp_link 同构）：摇杆/扳机/按键位图/控制锁打包成 32B 帧，**100Hz 固定节拍**经 UART 直连 F407 的 USART3；
- **心跳**：无论手柄连否都发帧——帧本身就是 C3 的存活心跳（F407 500ms 收不到帧即停车）；
- **本地控制锁**：Share 长按 1.5s 翻转（带震动确认反馈），锁值随帧上报，仲裁在 F407；
- **状态灯**：板载蓝灯呼吸/频闪/常亮三态指示连接状态。

## 2. 工程意义

1. **F407 没有 BLE**：Xbox 手柄只走 BLE，主控收不了，必须有一个桥。
2. **BLE 与 WiFi 不能共存于一颗芯片**（项目早期实测踩坑）：S3 同时跑 WiFi AP 和 BLE 会导致连接极不稳定，所以手柄桥单独用一颗 C3，与 WiFi 物理隔离。
3. **锁键本地化**：Share 长按翻锁的时序逻辑（计时、防抖、防残留按键）放在离手柄最近的 C3，F407 只消费结果——避免 100Hz 串口抖动干扰长按判定。
4. **稳定 100Hz 心跳**：`vTaskDelayUntil` 绝对节拍保证帧间隔精确，F407 才能可靠地做 500ms 失联判定。

## 3. 功能与作用

| 功能 | 实现 |
|---|---|
| BLE 连接管理 | MAC 白名单过滤（`68:6c:e6:42:57:89`），onLoop 自动扫描/连接/重连，首通知 5s 看门狗 |
| 状态读取 | 每 10ms 读快照：摇杆×4（0-65535，中位 32768）、扳机×2（0-1023）、按键位图、电量 |
| 帧打包 | 32B 帧（SOF 0xAA55 + LEN 27 + type 0x10 + body 26B + CRC16），小端 |
| 100Hz 心跳 | 无论手柄连否都发，兼作 C3 存活信号 |
| 控制锁 | Share 长按 1.5s 翻转（朴素计时，刻意不做 HID 新鲜度门控），翻转后震动反馈 |
| 状态灯 | GPIO8 蓝灯（低电平点亮）：呼吸=未连，频闪=连接沿，常亮=已连 |

## 4. 与其它三端的联系

```
        ┌──────────────────────────────────┐
        │       上位机（PC，Python）        │
        └───────────────┬──────────────────┘
                        │ （经 S3，与本工程无关）
        ┌───────────────▼──────────────────┐
        │     ESP32-S3（WiFi 桥）           │
        └───────────────┬──────────────────┘
                        │ USART2
        ┌───────────────▼──────────────────┐
        │   STM32F407（主控执行器）         │
        └───────────────▲──────────────────┘
                        │ USART3 115200（100Hz 手柄帧）
        ┌───────────────┴──────────────────┐
        │  ESP32-C3（手柄 BLE 桥，本工程）★ │
        └───────────────▲──────────────────┘
                        │ BLE
                    Xbox 手柄
```

- **↔ STM32F407**：C3 UART1（GPIO4=TX/GPIO5=RX）直连 F407 USART3（115200），100Hz 发帧；F407 负责死区/映射/仲裁/急停。
- **↔ 上位机 / ESP32-S3**：无直接连接——C3 完全不碰 WiFi，与 S3 物理隔离、各管一条链路。

## 5. 主要实现

### 5.1 任务结构（3 任务）

| 任务 | 优先级 | 栈 | 职责 |
|---|---|---|---|
| xbox_send | 6 | 4096 | 100Hz 心跳：读快照 → 填帧 → 维护锁 → UART 发送 → 通知状态灯（不依赖 BLE，连接/重连期间照发离线帧） |
| xbox_ble | 5 | 6144 | 独占 asukiaaa 库：begin() + onLoop() + 首通知看门狗 + 震动消费，20ms tick |
| led_status | 1 | 2048 | 20ms 周期驱动状态灯三态状态机 |

任务拆分要点：锁状态、fill_state、update_lock、UART 发送全在 sender 任务独占，无需加锁；震动写入必须由 BLE 任务执行（避免跨任务碰库内连接句柄）。

### 5.2 帧格式（与 esp_link 同构）

`SOF(0xAA 0x55) + LEN(1B=27) + type(0x10) + body(26B) + CRC16(2B)`，总长 **32B**，CRC16-CCITT 覆盖 SOF..body 共 30 字节（标准向量 0x29B1）。body 字段（`c3_gamepad_payload_t`，`static_assert(sizeof==26)`）：

| 字段 | 类型 | 语义 |
|---|---|---|
| seq | u32 | 有效 HID 通知计数（跨重连累加；电池/短报告不递增） |
| disc_gen | u32 | 断连代次（每次掉链 +1） |
| connected | u8 | 已连且有数据 |
| battery | u8 | 电量 0-100（%） |
| input_fresh | u8 | C3 本地判定「5s 内有有效 HID」 |
| joy_lx/ly/rx/ry | u16×4 | 摇杆 0-65535，中位 32768 |
| trigger_lt/rt | u16×2 | 扳机 0-1023 |
| buttons | u16 | 按键位图（bit0=A、bit1=B、bit2=X、bit3=Y、bit4=LB、bit5=RB、bit6=START、bit7=SELECT、bit8=SHARE、bit9=LS、bit10=RS、bit11-14=十字键、bit15=XBOX） |
| lock | u8 | 控制锁：0=手操、1=自主 |

### 5.3 BLE 细节

- 目标 MAC 过滤：`PEO_XB_TARGET_MAC "68:6c:e6:42:57:89"`（置空 = 按外观自动扫描）。
- `onLoop()` 每 20ms 调一次，内部自动扫描/连接/重连状态机，**可能同步阻塞**（连接段阻塞期间心跳照发，不依赖它）。
- 首通知看门狗：链路已连但 5s 内无首个有效 HID → 强制断连重连（判据用 `isWaitingForFirstNotification()`，不是 `snapshot.connected`）。
- 发送节拍：`vTaskDelayUntil` 绝对 10ms 周期（`vTaskDelay` 会被 `uart_wait_tx_done` 的 2.78ms 吃掉周期，实际变 ~77Hz，所以必须用绝对节拍）。

### 5.4 控制锁（Share 长按）

- `XB_LOCK_BTN=XB_BTN_SHARE`、`XB_LOCK_HOLD_MS=1500U`。
- 朴素长按：按下计时 → 1.5s 翻转 → 置 triggered；松开复位；触发后须观察到松开才能再触发。
- **刻意不做 HID 新鲜度门控**：Xbox 手柄只在输入**变化**时发 HID 报告，按住期间没有新报告——若做「新鲜度门控」会在按住 ~100ms 后计时归零、永远攒不到 1.5s（实机报过「长按没反应」，已回退此方案）。
- 翻转成功 → 震动反馈（双马达 80% × 0.3s，由 BLE 任务消费写 HID）+ 日志。
- **B 键（急停）在 C3 零处理**：只把 bit1 收进位图原样上发，急停判定与仲裁全在 F407。

## 6. 功能的影响与制约

- **100Hz 帧是 F407 失联判定的基础**：C3 任何任务卡死都会导致 F407 500ms 停车——所以 xbox_send 任务不依赖 BLE（BLE 连接阻塞时心跳照发），任务栈/节拍都保守设计。
- **锁在 C3 翻转、仲裁在 F407**：C3 断线期间锁无法翻转（物理上不可能），F407 侧默认手操态；锁值随帧上报，帧丢了锁状态也跟着丢（F407 以最新帧为准）。
- **C3 只发原始值**：死区/曲线/满速映射全在 F407——改手感不用重烧 C3（项目明确的设计决策）。
- **GPIO 占用约束**：GPIO20/21 被板载 USB 串口占用，不可用作链路脚；GPIO8 是 strapping 脚，用作 LED 时接法必须保证上电保持高电平（灯灭）。
- **BLE begin() 失败 = 死循环需重启**：sender 照发离线心跳（F407 不会误判失联），但 BLE 栈初始化失败无法自愈，只能重启。
- **震动必须 BLE 任务写**：sender 跨任务写 HID 会与库内部连接句柄竞态——这是任务拆分的硬约束。

## 7. 技术栈与构建

- 芯片：ESP32-C3 SuperMini（单核 160MHz、4MB flash）；ESP-IDF v6.1 + NimBLE（esp-nimble-cpp ^2.6.0）+ asukiaaa Xbox 手柄库本地封装。
- 构建：`./build.ps1`；烧录：`idf.py -p COMx flash monitor`。
